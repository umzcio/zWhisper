# AGENTS.md — zWhisper

Guidance for AI coding agents working in this repository. Read this before touching code.

## Project overview

zWhisper is a macOS AI voice-to-text dictation app (a SuperWhisper-style tool): hotkey-triggered recording from the menu bar, Whisper-based transcription (local via WhisperKit or cloud BYOK), optional per-mode LLM post-processing, and auto-paste into the focused app. Pipeline: **Dictation → Transcription → Mode processing → Auto-paste**.

The repository is a monorepo with two deliverables plus two authoritative design documents:

| Path | What it is |
|---|---|
| `app/` | React/TypeScript **web prototype** — the full product UX, simulated end-to-end with mock data (no real audio or APIs). It is the visual/interaction source of truth for the native app. |
| `zwhisper-mac/` | Native Swift/SwiftUI macOS app — the actual end product. **Feature-complete through M7** (M0 skeleton, M1 hotkeys & popover, M2 audio & waveform, M3 transcription, M4 paste & history, M5 modes engine, M6 management screens, M7 polish & intelligence: PTT, context capture, auto-activation, onboarding, Usage stats, reduced motion, Sparkle). |
| `zwhisper-design-spec.md` | Design handoff spec (tokens, component anatomy, motion/springs, screen-by-screen spec, Swift API mapping). |
| `zwhisper-swift-architecture.md` | **Implementation source of truth** for the native app: module breakdown, dictation state machine, audio pipeline, milestones M0–M7, risks. |
| `info.md` | Research notes on the SuperWhisper feature set being replicated. |

Key product concepts (used throughout both codebases): **Modes** (built-in: Email, Message, Note, Meeting, Voice Note, Write for me, Super; each with AI instructions and a ⌘1–7 shortcut), **Models** (tiered local Whisper models + cloud providers with BYOK), **History** (local JSON recordings with playback/reprocess), **Vocabulary** (custom words + text replacements), **Settings** (General / Sound / Shortcuts / Usage tabs).

## Repository layout

### `app/` — web prototype

- Stack: React 19, TypeScript ~5.9, Vite 7, Tailwind CSS 3.4 (shadcn theme), react-router 7, Radix UI primitives, Framer Motion + GSAP, lucide-react icons, zod, react-hook-form.
- Node.js 20; npm with committed `package-lock.json`.
- `src/pages/` — top-level routes: `Home`, `Modes`, `History`, `Models`, `Vocabulary`, `Settings` (wired in `src/App.tsx` under a shared `Layout`).
- `src/components/` — feature components (`RecordingPopover.tsx`, `Waveform.tsx`, `Navbar.tsx`, `ModeSwitcher.tsx`, `TrafficLights.tsx`, …) plus feature subfolders `modes/`, `models/`, `history/`, `vocabulary/`, `settings/`.
- `src/components/ui/` — shadcn/ui primitives (40+). Import as `@/components/ui/button` etc. Do not hand-edit these; add new ones via the shadcn pattern.
- `src/lib/` — `store.tsx` (React-context app state: theme, active mode, popover visibility, summon signal), `modes.ts` (mode definitions incl. scripted `script` → `processed` text pairs), `mockEngine.ts` (simulated recording/transcription engine — phases idle/recording/transcribing/processing/pasted/cancelled; treat its timings as the UX budget), `utils.ts` (`cn()` helper).
- `src/index.css` — global styles + CSS design tokens (`--stage`, `--surface-1..3`, `--text-1..3`, `--zw-accent`, …) mapped into Tailwind via `tailwind.config.js`. Dark theme is default; light/dark toggled by class on `<html>`.
- Path alias: `@` → `src/` (Vite + tsconfig).
- Settings persistence in the prototype uses `localStorage` (keys mirror the `zw-settings:*` list in the design spec §6.6).

## Build and test commands

### Web prototype (`app/`)

```sh
cd app
npm install
npm run dev       # Vite dev server on port 3000
npm run build     # tsc -b && vite build (type-check + production build)
npm run lint      # eslint .
npm run preview   # preview production build
```

There is no test suite for the web prototype; verification is `npm run build` (type check) + `npm run lint` + manual exercise in the dev server.

### Native app (`zwhisper-mac/`)

```sh
cd zwhisper-mac
brew install xcodegen   # once
xcodegen generate       # regenerate zWhisper.xcodeproj after any project.yml change
xcodebuild test -project zWhisper.xcodeproj -scheme zWhisper -destination 'platform=macOS'
```

CI (`.github/workflows/ci.yml`) runs exactly this on `macos-26` with the image's default Xcode, only for changes under `zwhisper-mac/**`, with `CODE_SIGNING_ALLOWED=NO`.

## Code style guidelines

- **Follow the two spec documents.** `zwhisper-swift-architecture.md` is the implementation source of truth; `zwhisper-design-spec.md` owns visuals and motion. Motion values come from spec §5.1, geometry from §3/§6 — never invent values. If `src/` and the design spec conflict, `src/` wins and the spec should be updated.
- TypeScript/React: functional components, strict TS, ESLint flat config (`eslint.config.js`: typescript-eslint recommended + react-hooks + react-refresh). Use the `@/` alias, Tailwind utility classes with the design-token colors, and `cn()` from `@/lib/utils` for conditional classes.
- Swift: Swift 6 language mode with strict concurrency; `PersistenceStore` is an `actor` (JSON files in `~/Library/Application Support/zWhisper/`, atomic writes, 500 ms debounce for high-churn stores — architecture §7). Default to no comments; where the code implements a specific spec/architecture section, referencing the section (e.g. "per architecture §7") is the existing convention.
- Keep the milestone discipline from architecture §9: each milestone M0–M7 has a "done when" bar; don't merge work past its milestone's scope, and don't pull deferred dependencies (Settings, Sparkle, sandbox entitlements) in early.

## Testing instructions

- Native app: Swift Testing tests live in `zwhisper-mac/Tests/zWhisperTests/` and run via the `xcodebuild test` command above (also run by CI). Existing coverage: `PersistenceStore` (first-launch nil, round-trip, atomic writes, debounce coalescing), `AppState` popover (summon/dismiss, toggle, Esc cancel timing, size toggle), `AppState` dictation with a mock `AudioCaptureEngineProtocol` (start/stop/cancel, permission-denied path, active-duration auto-stop, level forwarding, settings propagation, metering), `AppState` transcription flow with a mock `TranscriptionEngineProtocol` (model gating, partials, stop → transcribing → final, Esc during transcribing, vocabulary wiring), `AppState` paste & history flow with a mock `PasteControllerProtocol` (pasting/pasted phases, history entries, auto-paste off, undo paste, empty-transcript no-op), `AppState` modes flow with a mock `ModeProcessorProtocol` (Voice Note identity, streamed rewrite, ⌘-digit live switch, cycle order, reprocess with undo stack, processing failure), `ModeProcessor` backend selection + `CloudLLMBackend` SSE parsing, `PasteController` against the real clipboard (serialized — tests share `NSPasteboard.general`), and `WaveformModel` (idle/live/settle bar math). Note: XcodeGen writes explicit file lists — re-run `xcodegen generate` after adding any source or test file. The test target uses the app as its host (`TEST_HOST`).
- Web prototype: no automated tests — run `npm run build` and `npm run lint` before considering work done, and manually verify the flow (summon popover → record → transcribe → process → paste) in `npm run dev`.

## Security considerations

- No sandbox entitlements on the direct build (architecture §2); the Mac App Store path is explicitly deferred — do not add entitlements.
- The app requires Accessibility permission (auto-paste, push-to-talk focus guard) and microphone permission (`NSMicrophoneUsageDescription` in the plist); without AX permission, PTT must be disabled rather than risk a stuck recording (architecture risk 10.1).
- BYOK cloud API keys must go to the Keychain (design spec §8); never hardcode keys or commit secrets.
- `zwhisper-mac/project.yml` checklist for new build configurations (architecture risk 10.7): `OTHER_LDFLAGS` must contain `-weak_framework Combine` (KeyboardShortcuts fails at runtime, not link time, without it — a pre-build script enforces this; keep it in every target linking KeyboardShortcuts), deployment target stays at macOS 26.0 (Foundation Models floor — architecture §2).
- Local dev code signing uses `CODE_SIGN_IDENTITY = "-"`; CI builds with `CODE_SIGNING_ALLOWED=NO`.
